## Goal
Run PayFlow's data layer in the kind cluster, written by hand: a `payflow-dev` namespace with Pod Security labels, PostgreSQL as a StatefulSet with persistent storage, Redis as a Deployment, and the tables created by **Alembic migrations run as Kubernetes Jobs** instead of `create_all` at app startup. The migration work also changed both APIs and compose in `payflow-app`.

## What I did
1. **Namespace** — `k8s/raw/00-namespace.yaml` (files numbered so `kubectl apply -f k8s/raw/` applies them in order). Labels: `app.kubernetes.io/part-of: payflow`, `environment: dev`, and Pod Security Admission: `enforce: baseline`, `warn: restricted`, `audit: restricted`.
   ```bash
   kubectl create ns payflow-dev --dry-run=client -o yaml > k8s/raw/00-namespace.yaml
   kubectl apply -f k8s/raw/00-namespace.yaml
   kubectl get ns payflow-dev --show-labels
   ```
2. **Credentials, kept out of Git** — `postgres.env.example` (placeholders, committed), `postgres.env` (real values, in `.gitignore`), Secret created from the real file:
   ```bash
   echo "k8s/raw/postgres.env" >> .gitignore
   kubectl -n payflow-dev create secret generic postgres-credentials --from-env-file=k8s/raw/postgres.env
   ```
3. **PostgreSQL** — headless Service `10-postgres-service.yaml` (`clusterIP: None`) and StatefulSet `11-postgres-statefulset.yaml`: `postgres:17.11`, `serviceName: postgres`, `envFrom` the Secret, `PGDATA=/var/lib/postgresql/data/pgdata` (a subfolder, so `initdb` owns it), `volumeClaimTemplates` 1Gi on kind's `standard` StorageClass, `pg_isready` readiness/liveness probes, requests 100m/256Mi + 512Mi memory limit, non-root (UID 999, `fsGroup` 999, seccomp, no privilege escalation, all capabilities dropped).
4. **Redis** — ClusterIP Service `20-redis-service.yaml` and Deployment `21-redis-deployment.yaml`: `redis:7.4.11`, `--save "" --appendonly no --maxmemory-policy noeviction`, `redis-cli ping` probes, `emptyDir` at `/data`, fully `restricted` securityContext including `readOnlyRootFilesystem`.
5. **Alembic in accounts-api** (payflow-app) — `alembic>=1.13` in runtime dependencies (installed 1.20.1), `alembic init migrations`, `env.py` reads only `DATABASE_URL` and uses its own version table `alembic_version_accounts` + an `OWNED_TABLES = {"accounts"}` filter. First migration autogenerated against a throwaway Postgres, reviewed, then `create_all` removed from `lifespan`. `alembic.ini` + `migrations/` copied into the runtime image.
   ```bash
   docker run --rm -d --name alembic-pg -e POSTGRES_PASSWORD=dev -p 5433:5432 postgres:17.11
   export DATABASE_URL=postgresql+psycopg://postgres:dev@localhost:5433/postgres
   alembic revision --autogenerate -m "create accounts table"   # → 826d66998239
   ```
6. **Alembic in payments-api** — same setup, version table `alembic_version_payments`, `OWNED_TABLES = {"transactions"}` so the `accounts` stub table in `models.py` (only there so the foreign keys resolve) is never created or dropped by payments. Accounts migrated first in the throwaway DB, then:
   ```bash
   alembic revision --autogenerate -m "create transactions table"   # → 404f7eedd3b1
   ```
7. **Compose** — two one-shot services, `accounts-migrate` and `payments-migrate` (same images as the APIs, `command: ["alembic", "upgrade", "head"]`, only `DATABASE_URL`). Order: postgres healthy → accounts-migrate exits 0 → payments-migrate exits 0; each API waits for its migration with `service_completed_successfully`. Pinned compose to `postgres:17.11` / `redis:7.4.11` to match the cluster. Reset the old volume (`docker compose down -v`). Merged as payflow-app PR #15.
8. **Images 0.2.0 into kind** — rebuilt from payflow-app `main`, tagged `ghcr.io/owais-io/payflow-<service>:0.2.0`, `kind load docker-image … --name payflow`.
9. **Migration Jobs** — `30-accounts-migrate-job.yaml` and `31-payments-migrate-job.yaml`: same image as the API, `alembic upgrade head`, `backoffLimit: 3`, `activeDeadlineSeconds: 300`, `restartPolicy: Never`, `automountServiceAccountToken: false`, fully `restricted` securityContext, labels on both the Job and its pod template. `DATABASE_URL` built from the Secret keys with `$(VAR)` expansion. Applied in order:
   ```bash
   kubectl apply -f k8s/raw/30-accounts-migrate-job.yaml
   kubectl -n payflow-dev wait --for=condition=complete job/accounts-migrate --timeout=120s
   kubectl apply -f k8s/raw/31-payments-migrate-job.yaml
   kubectl -n payflow-dev wait --for=condition=complete job/payments-migrate --timeout=120s
   ```
10. Merged as payflow-platform PR #23 (one branch for the task, a commit per item).

## Problems and fixes
| Problem (error message) | Cause | Fix |
|---|---|---|
| `cannot unmarshal object into … envFrom of type []v1.EnvFromSource`, then `cannot unmarshal string into … secretRef` | `envFrom` is a **list**, and `secretRef` is an **object** with `name:` | `envFrom: [ { secretRef: { name: postgres-credentials } } ]` |
| `unknown field "…env[0].PGDATA"` | Env vars are `- name: X` / `value: Y`, not `X: Y` | `- name: PGDATA` + `value: /var/lib/postgresql/data/pgdata` |
| `unknown field "…resources.limit"`, `cannot unmarshal array into … resources` | The key is `limits` (plural) and `resources` is a map, not a list | `resources: { requests: {…}, limits: {…} }` |
| Service and StatefulSet created in `default` | Files from `kubectl create … --dry-run` had no namespace | Added `metadata.namespace: payflow-dev`, deleted the stray objects |
| Redis Service had no endpoints | Service selector needed `part-of: payflow`, pod template didn't have it | Selector = `name` + `part-of`; template = those + `component` |
| `spec.selector: … field is immutable` | Changed the Deployment's selector after creating it | Deleted the Deployment and applied again |
| `status:` blocks in committed manifests | Left over from `--dry-run=client -o yaml` | Removed; status is written by the cluster, not by me |
| `Error from server (Conflict) … namespaces "payflow-dev": the object has been modified` | `00-namespace.yaml` was saved from `kubectl label … -o yaml` of the **live** object, so it carried `resourceVersion`, `uid` and the last-applied annotation | `kubectl delete -f k8s/raw/` and recreated; the file still needs cleaning (see Follow-ups) |
| `kubectl delete -f k8s/raw/` removed far more than expected | Deleting a namespace deletes **everything in it**: the Secret and the PVC (all data) too | Recreated the objects; remembered: never delete a namespace to "reset" one object |
| Job stuck: `CreateContainerConfigError`, then pod gone | `secrets "postgres-credentials" not found`: the Secret was deleted with the namespace earlier and never recreated. The Job hit `activeDeadlineSeconds: 300` and Kubernetes removed its pods | Recreated the Secret, `kubectl delete job` and applied again |

## Open follow-ups
- Local venvs run Python 3.14, the images 3.12. Recreate the venvs with `python3.12 -m venv .venv`.
- Redis has no persistence by design: notifications in flight are lost if it restarts. Revisit if PayFlow needs guaranteed delivery.

## What I learned
- **StatefulSet vs Deployment.** A StatefulSet gives a stable pod name (`postgres-0`), stable DNS and its own PVC per pod (`data-postgres-0`) that survives the pod. Postgres needs that; Redis here is a disposable message channel, so a Deployment is enough.
- **Headless vs ClusterIP Service.** `clusterIP: None` → DNS returns the pod IP directly (`postgres-0.postgres…`). ClusterIP → DNS returns a virtual IP and kube-proxy load-balances. The StatefulSet's `serviceName` must match the headless Service.
- **DNS search domains.** A short name like `redis` is tried against `payflow-dev.svc.cluster.local`, `svc.cluster.local`, `cluster.local`; busybox prints every miss as `NXDOMAIN`. A trailing dot (`redis.payflow-dev.svc.cluster.local.`) skips the search list.
- **Labels and selectors.** A Service selects pods that have **every** selector label. Keep selectors small and stable (`name` + `part-of`) because Deployment/StatefulSet selectors are immutable. Labels on a Job don't reach its pods: label the pod template too.
- **Pod Security Admission.** `enforce: baseline` + `warn/audit: restricted` lets workloads run while every `apply` lists what `restricted` would reject — a to-do list instead of a wall.
- **Secrets stay out of Git**: `.env.example` committed, `.env` ignored, Secret created with `--from-env-file`. Changing the Secret later doesn't change the password Postgres stored when it first initialized the PVC.
