## Goal
Package every part of PayFlow as a container image that is small, runs as non-root, is built
from a pinned base, and tells you what it is (labels) and whether it is alive (health check).
These images are what CI will build and push in 2.5 and what Kubernetes will run from Phase 3.

## What I did
1. **accounts-api: multi-stage Dockerfile (2.1.1).** A `builder` stage creates a virtualenv at
   `/opt/venv` and runs `pip install .`; the `runtime` stage starts from a clean slim image and
   copies only `/opt/venv`. `build/`, `*.egg-info`, `tests/` and `pyproject.toml` never reach the
   final image, and the app lives in `site-packages`, so `/app` is empty.
   ```dockerfile
   FROM ${PYTHON_IMAGE} AS builder
   RUN python -m venv /opt/venv
   ...
   RUN pip install .

   FROM ${PYTHON_IMAGE} AS runtime
   COPY --from=builder /opt/venv /opt/venv
   CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8001", "--no-access-log"]
   ```
   `--host 0.0.0.0` so the port is reachable from outside the container; exec-form `CMD` so
   uvicorn is PID 1 and receives SIGTERM.
2. **Non-root user with a fixed UID (2.1.2).** Created `payflow` with UID/GID 10001 in the
   runtime stage and set `USER 10001:10001`, numeric so Kubernetes `runAsNonRoot` can verify it.
   The venv is copied without `--chown`, so it stays root-owned and read-only to the app.
3. **Pinned base image (2.1.3).** Replaced the moving `python:3.12-slim` with tag and digest,
   defined once before the first `FROM` and used by both stages:
   ```dockerfile
   ARG PYTHON_IMAGE=python:3.12.16-slim-trixie@sha256:4840d514c583a4d3d8cad3940e68dee6f0f6f3635c12fcd0a3d74c21a5b93a54
   ```
   Digest taken from the multi-arch index (`docker buildx imagetools inspect`), not a
   single-platform manifest.
4. **`.dockerignore` as an allowlist (2.1.4).** `*`, then `!pyproject.toml` and `!app/`, then
   `**/__pycache__` and `**/*.pyc`. Proved `.env` stays out with a throwaway busybox build that
   runs `find` on the build context.
5. **HEALTHCHECK and OCI labels (2.1.5).** The slim image has no curl, so the check uses Python:
   ```dockerfile
   HEALTHCHECK --interval=30s --timeout=3s --start-period=10s --retries=3 \
     CMD ["python", "-c", "import urllib.request; urllib.request.urlopen('http://127.0.0.1:8001/healthz', timeout=2)"]
   ```
   It calls `/healthz`, not `/readyz`: a database outage must not mark the app container
   unhealthy. Labels `source`, `version`, `revision`, `title` and `licenses`; version and
   revision come from `--build-arg`, declared late in the stage so a new version does not
   rebuild the venv layer.
6. **payments-api and notification-worker (2.1.6).** Copied the accounts-api files and changed
   only what differs. `diff` against accounts-api showed only the intended lines. payments-api:
   title and port 8002. notification-worker: title, `CMD ["python", "-m", "app.main"]`,
   `EXPOSE 9100`, and a health check on `/metrics` (it has no `/healthz`).
7. **Frontend (2.1.7).** Single stage on `nginxinc/nginx-unprivileged:1.30.6-alpine` (pinned by
   digest), UID 101, port 8080. Found the newest stable tag (even minor = stable) with:
   ```bash
   curl -s "https://hub.docker.com/v2/repositories/nginxinc/nginx-unprivileged/tags?name=alpine&page_size=100" \
     | jq -r '.results[].name' | grep -E '^1\.[0-9]*[02468]\.[0-9]+-alpine$' | sort -V | tail -1
   ```
   Its own `nginx.conf` serves only the static files, answers `/healthz` itself, hides the
   nginx version and adds `nosniff`, `X-Frame-Options: DENY` and `Referrer-Policy: no-referrer`.
   No `/api` routing: that is the Ingress's job. Health check with busybox `wget`; no `CMD`,
   the base image's `nginx -g 'daemon off;'` is kept.
8. **Commit (2.1.8).** Updated the four `1.27-alpine` references (README, frontend README, dev
   config comment) to `1.30.6-alpine` and added a "Container images" section to the README.
   Merged as payflow-app PR # 9.

## Problems and fixes
| Problem (error message) | Cause | Fix |
|---|---|---|
| `failed to parse stage name ... invalid reference format` | Wrote `python:3.12.16-slim-trixie:sha256:...`, a colon before the digest | An image reference is `name:tag@digest`; changed `:sha256` to `@sha256` |
| `docker.io/nginx/nginx-unprivileged:1.30.6-alpine@sha256:...: not found` | Took the digest from `nginxinc/nginx-unprivileged` but wrote `nginx/nginx-unprivileged`: two separate repos, and a digest is looked up inside the repo you name | Name, tag and digest all from the same `imagetools inspect` output |
| `failed to bind host port 0.0.0.0:8080/tcp: address already in use` | Host Jenkins (`java`, found with `sudo ss -ltnp 'sport = :8080'`) | `-p 8081:8080`; the container still listens on 8080 |
| `bind() to 0.0.0.0:8080 failed (98: Address in use)` with `--network host` | Host networking has no port mapping, so nginx binds the host's 8080 | `sed` copy of the dev config with `listen 8081`, plus `--no-healthcheck` (the check would have hit Jenkins) |

## What I learned
- **Multi-stage is about what ships, not how you build.** The builder can be as messy as it
  needs; only the venv crosses into the runtime image. The frontend has nothing to build, so it
  is single-stage.
- **A numeric UID is a security property Kubernetes can check.** `USER payflow` could be UID 0
  for all the kubelet knows; `USER 10001:10001` can be verified by `runAsNonRoot`.
- **Root-owned code is read-only code.** Files from `COPY` without `--chown` belong to root, so
  the app user can run its code (venv, HTML) but not change it.
- **A tag is a name, a digest is the content.** Tags move; the digest pins the exact bytes. Keep
  the tag for people and the digest for Docker, and let a bot bump both later.
- **Allowlist `.dockerignore`:** anything new is excluded by default, which is the safe failure
  for secrets like `.env`.
- **Liveness is not readiness.** The health check uses `/healthz` so a database blip does not
  get a healthy app restarted.

## Carried forward
- **`uvicorn.access` lines** show up every 30 s for the health check even though `CMD` has
  `--no-access-log`. The logging config probably re-enables that logger. Kubernetes probes will
  add the same noise.
- **The worker's health check only proves the process and its metrics thread are up**, not that
  the Redis loop is still processing. Detecting a stuck worker is a metrics/alerting job (Phase 5).
- **Docker `HEALTHCHECK` is ignored by Kubernetes:** liveness/readiness probes go in the Helm
  chart (3.x).
- **Read-only root filesystem (Phase 4):** the nginx entrypoint already logs
  `can not modify /etc/nginx/conf.d/default.conf (read-only file system?)` when the config is
  mounted read-only. It is harmless, but expect it.
- **Pinned digests need updating:** add Renovate or Dependabot for base images later.

## Interview angle
**Q: How do you harden a container image for a payments service?**
A: Start from a slim, pinned base (tag plus digest), build in a separate stage and ship only the
runtime artifacts, run as a fixed numeric non-root UID so Kubernetes can enforce `runAsNonRoot`,
keep the application files root-owned so the process cannot modify them, and keep secrets out
of the build context with an allowlist `.dockerignore`. Then scan it (Trivy, 2.3) and let the
cluster enforce the rest with `securityContext` and Kyverno.
